# SMALL protocol profile v2.0.0

This document is normative for the session-capable profile. The frozen v1.0.0
specification remains normative for unmigrated v1 workspaces.

## Identity and policy

`project_id`, `lineage_id`, `session_id`, `event_id`, and native `task_id` are
opaque 128-bit-or-greater random identifiers generated by the CLI. Readable
labels and imported v1 aliases are non-unique display metadata. `replayId` is
preserved as v1 lineage metadata only.

New and migrated workspaces default to `solo` unless migration explicitly asks
for `collaborative`. A policy transition records prior/new mode, requester label,
rationale, and expected frontier. It cannot delete history, weaken acceptance,
or enter solo mode while multiple unresolved active ownership claims exist.

## Authoritative tracked layout

```text
.small/
  profile.json
  policy/intent.small.yml
  policy/constraints.small.yml
  sessions/<session-id>.json
  events/<session-id>/<event-id>.json
  receipts/sha256/<digest>.json
  imports/v1/<import-id>/{manifest.json,originals/...}
```

The following are ignored local state under `.small-cache/`: writer lock,
active-session pointer, command logs, transaction journals, indexes, and
generated plan/progress/handoff/resume views. No tracked active-machine pointer,
absolute machine path, or project-wide last-modified timestamp is permitted.

## Canonical records

JSON is UTF-8, duplicate-key-free, with object keys sorted lexicographically,
no insignificant whitespace, integers only for numeric protocol fields, and a
maximum record size of 1 MiB. A record digest is SHA-256 of canonical JSON after
removing its top-level `digest`. Non-finite or fractional numeric values fail.

A session descriptor contains profile/project/lineage/session identity,
optional label and provenance labels, optional parent handoff/event, the
observed frontier, CLI version, and creation time. Resuming a clone creates a new
session linked to its predecessor; a writable session ID is never blindly reused.

Each event contains: profile/project/lineage/session/event identity, kind,
per-session positive sequence, previous event when sequence is greater than one,
explicit observed parent event IDs, occurrence time annotation, typed payload,
and digest. Task events also carry stable task ID, task revision, and observed
policy/source revisions where applicable.

Events are published durably with exclusive create. Existing identical ID and
content is idempotent. Existing identical ID with different canonical content is
corruption. Missing parents, cycles, sequence gaps, prior-event mismatches,
cross-project references, oversized records, unknown fields, and digest mismatch
fail validation.

## Event kinds and task semantics

Required kinds are `session_started`, `session_closed`, `task_created`,
`task_updated`, `task_transitioned`, `command_recorded`, `handoff_recorded`,
`mode_changed`, `policy_changed`, `ownership_claimed`, `ownership_taken_over`, `conflict_resolved`,
and `v1_imported`.
`policy_changed` binds reviewed intent and constraint byte digests to a new
content-derived policy revision in the same state transaction as the files.

Command outcome is not task lifecycle. `command_recorded` captures bounded child
outcome and producer metadata. A completed or blocked task is accepted only by a
`task_transitioned` checkpoint whose evidence meets the task revision's stated
requirements. Later policy, acceptance, or source revisions make earlier
evidence historical and potentially inapplicable; they do not erase it.

## Reduction and reconciliation

Event-set ingestion is idempotent, commutative, and associative. Per-session
links and observed parents establish causality. Independent events have a stable
display order only; occurrence time never chooses authority.

The reducer combines independent tasks. Concurrent incompatible transitions,
changed policy/acceptance, session-chain forks, missing receipts, competing
takeovers, divergent mode changes, and concurrent resolutions produce explicit
conflicts. Semantically equivalent completions may be grouped when task,
policy, source candidate, and evidence identities match, while every attestation
is retained. Task aliases never identify tasks.

A resolution references every competing head, a selected outcome, the resolver
session, rationale/evidence, and exact expected frontier. A changed frontier
causes `stale_frontier`; concurrent resolutions remain conflicted unless a later
event causally supersedes them. Inspection remains available during conflict;
strict authoritative handoff does not.

## Evidence receipts

Evidence strength is one of `narrative_assertion`, `cli_captured`, or
`verified_artifact`. Availability is one of `unavailable`, `stale`, `failed`, or
`verified`. Portable receipts record producer, task/policy/source revisions,
command or validator identity, outcome, bounded metadata, artifact-relative path,
size, and digest. Verification never follows traversal or symlink escapes, reads
unbounded files, fetches URLs, or executes embedded commands. A valid receipt
proves what was recorded, not whether the check was adequate or the producer
trustworthy.

## Migration and compatibility

Migration is preview then apply against an expected input digest. Preview is
read-only. Apply retains every v1 canonical byte in an immutable import bundle,
records per-file digests and deterministic mapping IDs, and then installs v2
authority through a recoverable transaction. Imported event IDs derive from a
caller-visible import namespace, original artifact kind, entry ordinal, and
complete bytes so repeated identical entries remain distinct.

Independent clone migration deduplicates a proven common baseline only when the
same explicit import namespace and manifest are used. Ambiguous same-alias tasks
require mapping. Legacy tracked files become archived originals, not parallel
authority. A migrated profile may contain stray legacy writes from unsupported
old CLIs; new strict validation reports them. The project does not promise that
arbitrary historical binaries understand or safely refuse v2.

Migration is idempotent for the same plan, refuses changed input, and leaves
either v1 authority, complete v2 authority, or an explicit recoverable journal.
There is no lossless v2-to-v1 downgrade.
